## 1. Boton "Descargar plantilla CSV" da 404

### Sintoma
GET `/api/v1/plantilla-inscripcion` → 404 "No static resource"
El endpoint existe en `InscripcionController.java` linea 205 pero no se compila en el .class.
Causa raiz desconocida: el metodo esta en el fuente, compila sin errores, pero no aparece en el bytecode.

### Solucion aplicada
Se creo `PlantillaController.java` separado con el mismo endpoint. Funciona.

### Archivo
`src/main/java/com/lms/controller/PlantillaController.java` (NUEVO)

## 3. Modal "Forzar Completado" se corta visualmente

### Sintoma
El pop-up se ve parcialmente detras de otros contenedores. El z-index no es suficiente o un contenedor padre tiene `overflow: hidden` o `transform`.

### Archivo
`src/main/resources/templates/cursos/participantes.html` (lineas del modal Forzar Completado)

### Solucion
Agregar `position: fixed; z-index: 9999;` al modal y verificar que ningun contenedor padre tenga `overflow: hidden` o `transform`.

## 4. "Forzar Completado" da 403 Forbidden

### Sintoma
POST `/api/v1/inscripciones/{id}/forzar-completado` → 403 Forbidden
El body se envia correctamente: `{"motivo":"Falla tecnica SCORM","comentario":"error de internet"}`

### Causa raiz
CSRF token faltante en la peticion POST. El boton "Forzar Completado" usa HTMX o fetch normal sin incluir el header `X-XSRF-TOKEN`.

### Archivo
`src/main/resources/templates/cursos/participantes.html` (linea ~815, funcion forzarCompletado)

### Solucion
Verificar que el handler `htmx:configRequest` en `head.html` este agregando el token CSRF a todas las peticiones. Si el boton usa fetch() en vez de HTMX, agregar manualmente el header.

---

## 5. Problema general con CSRF a nivel de todo el proyecto — SOLUCION DEFINITIVA

### Analisis
El CSRF esta habilitado en `SecurityConfig.java` con `CookieCsrfTokenRepository`.
El token JWT viaja en cookie `access_token` con `SameSite=Lax` y `HttpOnly=true`.
Con SameSite=Lax, el navegador NO envia la cookie en requests cross-site de POST/PUT/DELETE.
Esto hace que la proteccion CSRF de Spring Security sea REDUNDANTE para los endpoints REST.

### Solucion definitiva
Excluir todos los endpoints `/api/v1/**` de CSRF en `SecurityConfig.java`:
```java
.ignoringRequestMatchers("/hx/admin/**", "/api/v1/**")
```

**Motivo:** La combinacion JWT + SameSite=Lax + HttpOnly ya protege contra ataques CSRF.

**Impacto:**
- ✅ Elimina TODOS los 403 CSRF de toda la API REST de un solo golpe
- ✅ Ya no se necesita el handler htmx:configRequest en head.html
- ✅ Ya no se necesita el input hidden _csrf en formularios
- ✅ Ya no hay que acordarse de CSRF al crear nuevos endpoints
- ❌ Se pierde proteccion CSRF para requests que no usen JWT (solo login de formulario — pero ese usa su propio CSRF via input _csrf de Thymeleaf)
