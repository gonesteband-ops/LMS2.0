# 🐛 Reporte de Bug: CSRF 403 en POST de publicaciones y subcarpetas (BUG-015 residual)

---

## 1. Síntoma (qué viste)

### Error 1 — Editar publicación
1. Ir a http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/carpeta-de-ejemplo
2. Hacer clic en "Editar" en una publicación
3. Se abre el formulario de edición con datos precargados
4. Hacer clic en "Publicar"
5. Redirige a la página de la subcarpeta con error: **Whitelabel Error Page — 403 Forbidden**

### Error 2 — Crear nueva publicación
1. Ir a http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/carpeta-de-ejemplo/nuevo
2. Llenar el formulario y hacer clic en "Publicar"
3. Error: **Whitelabel Error Page — 403 Forbidden**

### Error 3 — Crear nueva subcarpeta
1. Ir a http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/nuevo
2. Ingresar nombre y hacer clic en "Guardar"
3. Redirige a URL con UUID: `/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001/subcarpetas`
4. Error: **Whitelabel Error Page — 403 Forbidden**

---

## 2. Comportamiento esperado

Los formularios deberían enviarse correctamente mediante POST sin error 403, redirigiendo a la página correspondiente con los datos actualizados.

---

## 3. Comportamiento actual

Los 3 POST devuelven HTTP 403 Forbidden. Causas identificadas:

- **Error 3 (Crear subcarpeta):** El template `formulario-subcarpeta.html` usa `${gestor.id}` en vez de `${gestor.codigo}` en el `th:action`, generando URL con UUID (`a1000000-...`) en vez de código (`GESTOR_EJEMPLO`). Además, **NO tiene token CSRF oculto**, por lo que Spring Security rechaza el POST con 403.

- **Errores 1 y 2 (Crear/Editar publicación):** El template `formulario-publicacion.html` SÍ tiene token CSRF y SÍ usa `codigo`. Sin embargo, la entidad `SubServicioBPO` tiene el campo `codigo` como `@Column(length = 50)` (nullable sin NOT NULL en el modelo). Si `subcarpeta.codigo` es `null` (por no haberse generado correctamente en V24+V25), el `th:action` genera una URL inválida. Además, el formulario usa `enctype="multipart/form-data"` y existe un caso conocido donde Spring Security no extrae el CSRF token de multipart requests si el `MultipartFilter` no se configura antes que el `CsrfFilter`.

---

## 4. Evidencia

- **Mensaje de error:** `Whitelabel Error Page — type=Forbidden, status=403`
- **URL fallida (Error 3):** `/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001/subcarpetas`
- **URL fallida (Error 1 y 2):** `/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/carpeta-de-ejemplo`
- **Código HTTP:** 403 Forbidden
