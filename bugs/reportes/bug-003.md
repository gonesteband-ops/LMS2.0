# Reporte de Bug: Modulo ARCOP — Errores CSRF, UX y logica de negocio

---

## 1. Sintomas detectados

### 1.1 Diseno y UX del modulo
La pagina `/dashboard/arcop` no mantiene la coherencia visual con el resto de la aplicacion. Los datos se muestran en formato JSON sin estructurar, lo que genera una mala experiencia de usuario.

### 1.2 Ver mis datos — GET /api/v1/arcop/acceso
Al hacer clic en "Ver mis datos", la respuesta JSON se renderiza como texto plano sin formato (pre/raw). Deberia mostrarse en una tabla o tarjetas con diseno limpio.

### 1.3 Rectificar datos — PUT /api/v1/arcop/rectificar
**HTTP 403 Forbidden.** El boton "Actualizar" no ejecuta la accion. El motivo es la ausencia del token CSRF en la peticion HTMX.

### 1.4 Solicitar eliminacion — DELETE /api/v1/arcop/suprimir  
**HTTP 403 Forbidden.** El boton rojo "Solicitar eliminacion" no ejecuta la accion. Mismo problema de CSRF. Ademas, no hay confirmacion previa (popup/confirmacion) antes de eliminar.

### 1.5 Bloquear cuenta — POST /api/v1/arcop/bloquear
**HTTP 403 Forbidden.** El boton "Bloquear cuenta" no ejecuta la accion. Mismo problema de CSRF.

---

## 2. Causa raiz

Todos los endpoints del modulo ARCOP (rectificar, suprimir, bloquear) devuelven 403 porque las peticiones HTMX no incluyen el token CSRF.

La aplicacion tiene CSRF habilitado en `SecurityConfig.java` con `CookieCsrfTokenRepository`. El token CSRF se almacena en la cookie `XSRF-TOKEN` (sin HttpOnly, accesible via JS). Sin embargo, el handler `htmx:configRequest` que deberia agregar automaticamente el header `X-XSRF-TOKEN` a las peticiones HTMX fue eliminado del `head.html`.

**Archivos involucrados:**
- `src/main/java/com/lms/security/SecurityConfig.java` (linea 49-52: CSRF activado)
- `src/main/resources/templates/fragments/head.html` (lineas 34-58: se elimino el handler CSRF para HTMX)
- `src/main/resources/templates/dashboard/arcop.html` (lineas 30-80: botones HTMX sin CSRF)

## 3. Comportamiento esperado

### 3.1 UX de "Ver mis datos"
Los datos deben mostrarse en un formato legible: tabla con filas para cada campo (nombre, email, rut, fechaNacimiento) y secciones para cursos, consentimientos y firmas.

### 3.2 Rectificar datos (PUT)
Al hacer clic en "Actualizar", debe enviar los datos al servidor y actualizar la BD sin error 403.

**Pregunta de negocio:** Si el usuario cambia su email, ?`debe poder iniciar sesion con el nuevo email? Si, el email es el identificador de login. El cambio debe actualizar el email en la tabla `usuarios` y el usuario debe poder loguearse con el nuevo email.

### 3.3 Solicitar eliminacion (DELETE)
Debe mostrar un popup de confirmacion: "?`Confirma la eliminacion de tu cuenta?" con botones "Si, eliminar" y "Cancelar". Solo si confirma, enviar el DELETE.

**Logica de negocio segun Ley 21.719:**
- La cuenta **NO se borra fisicamente** de la BD
- Se marcan los datos personales como anonimizados:
  - `nombreCompleto` = "Usuario Anonimizado"
  - `email` = "anon-{uuid}@deleted.local"
  - `rut` = NULL
  - `fechaNacimiento` = NULL
  - `estadoTratamiento` = "ANONIMIZADO"
  - `deletedAt` = NOW()
  - `bloqueadoHasta` = NOW() (no puede iniciar sesion)
- Los registros academicos (cursos completados, certificados) SE CONSERVAN pero sin identificar a la persona (solo el UUID queda como referencia)
- La accion debe registrarse en `solicitudes_eliminacion` con estado "COMPLETADA"

### 3.4 Bloquear cuenta (POST)
Debe marcar al usuario como bloqueado temporalmente.

**Logica de negocio:**
- `estadoTratamiento` = "BLOQUEADO"
- `bloqueadoHasta` = NOW() + 90 dias
- El usuario NO puede iniciar sesion mientras `bloqueadoHasta > NOW()`
- Al iniciar sesion con cuenta bloqueada, debe mostrar mensaje: "Tu cuenta esta bloqueada hasta el [fecha]"
- El usuario puede desbloquear su cuenta SOLO si inicia sesion (el `JwtAuthenticationFilter` debe verificar `bloqueadoHasta`)

## 6. Acciones requeridas

### 6.1 Restaurar handler CSRF en head.html
Agregar de vuelta el handler `htmx:configRequest` en `head.html` para que todas las peticiones HTMX incluyan el header `X-XSRF-TOKEN` con el valor del meta tag `_csrf`.

### 6.2 Mejorar UX de "Ver mis datos"
Reemplazar el `<pre id="acceso-data">` por una tabla HTML con formato. O usar tarjetas (cards) como en el resto del dashboard.

### 6.3 Agregar confirmacion a "Solicitar eliminacion"
Usar `confirm()` de JavaScript o un modal HTMX antes de enviar el DELETE.

### 6.4 Verificar estado de bloqueo en login
El `JwtAuthenticationFilter` debe validar que el usuario no este bloqueado antes de permitir la autenticacion.

### 6.5 Actualizar logica de negocio en ArcopService
- `solicitarSupresion()`: debe anonimizar datos en vez de solo marcar `deletedAt`
- `bloquear()`: debe setear `estadoTratamiento` y `bloqueadoHasta`
