# 🐛 Reporte de Bug: Gestor duplicado, Publicación sin vigencia, DB inconsistente y usuarios no cargan

---

## 1. Síntomas

### Error 1 — Duplicate key `cuentas_bpo_codigo_key` al crear gestor
1. Ir a `http://localhost:8080/admin/bpo/gestores/nuevo`
2. Ingresar código `EVA007` (o cualquier código ya existente)
3. Hacer clic en "Guardar"
4. Error 500: `duplicate key value violates unique constraint "cuentas_bpo_codigo_key"`

### Error 2 — Check constraint `vigencia_requerida_publicado` al publicar contenido
1. Ir a `http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/carpeta-de-ejemplo/publicaciones/c3000000-0000-0000-0000-000000000001/editar`
2. Hacer clic en "Publicar"
3. Error 500: `new row for relation "contenidos_bpo" violates check constraint "vigencia_requerida_publicado"`

### Error 3 — Migraciones Flyway V20-V26 no aplicadas (DB inconsistente)
1. Tras eliminar contenedores Docker y reiniciar, la app no arranca
2. Flyway falla porque las tablas BPO ya existen pero no están registradas en `flyway_schema_history`
3. Además, `V20__crear_modulo_bpo.sql` usa `CREATE TABLE` sin `IF NOT EXISTS`, lo que causa error en segundas ejecuciones

### Error 4 — Usuarios del Sistema no cargan (se queda en "Cargando usuarios...")
1. Ir a `http://localhost:8080/admin/usuarios`
2. La tabla de usuarios muestra "Cargando usuarios..." permanentemente
3. La petición HTMX a `/hx/admin/usuarios` obtiene 403/redirect por falta de autenticación o porque la app no inició correctamente

### Error 5 — Datos de seed V24 incompatibles con V25
1. `V24__seed_datos_ejemplo_bpo.sql` inserta en `subservicios_bpo` sin columna `codigo`
2. `V25__agregar_codigo_subservicios_bpo.sql` agrega `codigo` con `NOT NULL`
3. En orden secuencial (V24 antes que V25), V24 falla porque la columna `codigo` ya existe y es NOT NULL

---

## 2. Comportamiento esperado

- Crear gestor con código duplicado debe mostrar mensaje de error claro, no 500
- Publicar contenido debe auto-asignar vigencia o pedir fechas al usuario
- Flyway debe ejecutar migraciones de forma idempotente y la app debe arrancar siempre
- Los usuarios deben cargarse automáticamente al acceder a `/admin/usuarios`
- Los datos de seed deben ser compatibles con el schema final

---

## 3. Comportamiento actual

- Error 500 sin mensaje claro al duplicar código de gestor
- Error 500 al publicar porque `vigencia_desde` y `vigencia_hasta` son `null`
- Flyway falla al re-ejecutar V20 porque las tablas ya existen
- Los usuarios no cargan porque la app no inicia o la sesión expiró
- V24 falla en bases con V25 pre-aplicada

## 5. Causa raíz

### Error 1
`CuentaBPOService.crearCuenta()` guarda directamente sin validar unicidad del `codigo`. El campo es libre (input text) y cualquier código existente causa violación de unique constraint.

### Error 2
`ContenidoBPOService.crearPublicacion()` hardcodea `estado="publicado"` pero nunca asigna `vigenciaDesde`/`vigenciaHasta`. La DB exige ambos campos cuando `estado='publicado'` (constraint `vigencia_requerida_publicado`). El DTO `ContenidoBPOCreateDTO` no tiene campos de vigencia.

### Error 3
`V20__crear_modulo_bpo.sql` usa `CREATE TABLE` sin `IF NOT EXISTS`. Al recrear contenedores, la tabla ya existe en el volumen persistente de Postgres.

### Error 4
El HTMX request a `/hx/admin/usuarios` requiere autenticación. Si la app falló al arrancar (Error 3) o la sesión expiró, el request devuelve redirect a `/login` y HTMX no lo procesa.

### Error 5
`V24__seed_datos_ejemplo_bpo.sql` inserta en `subservicios_bpo` sin columna `codigo`. Si V25 (que agrega `codigo`) ya fue aplicada manualmente antes, el INSERT falla.

## 6. Archivos modificados para la corrección

| Archivo | Cambio |
|---------|--------|
| `src/main/java/com/lms/service/bpo/CuentaBPOService.java` | Validación de `codigo` y `nombre` duplicados antes de guardar |
| `src/main/java/com/lms/dto/bpo/ContenidoBPOCreateDTO.java` | Agregados campos `vigenciaDesde` y `vigenciaHasta` (LocalDateTime) |
| `src/main/java/com/lms/service/bpo/ContenidoBPOService.java` | `crearPublicacion()` asigna vigencia por defecto ahora()+1año; `cambiarEstado()` valida vigencia antes de publicar |
| `src/main/java/com/lms/controller/bpo/AdminBPOController.java` | `formularioEditarPublicacion()` pasa vigencia al DTO |
| `src/main/resources/templates/bpo/admin/formulario-publicacion.html` | Agregados campos `datetime-local` para vigencia desde/hasta |
| `src/main/resources/db/migration/V20__crear_modulo_bpo.sql` | `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, `INSERT ... WHERE NOT EXISTS` |
| `src/main/resources/db/migration/V24__seed_datos_ejemplo_bpo.sql` | Agregado `codigo` al INSERT de `subservicios_bpo` |
