# 🐛 Reporte de Bug: Seccion Privacidad — 5 errores de funcionalidad y UX

---

## Bug 1 — Finalidades del tratamiento no reflejan los consentimientos reales del usuario

### Sintoma
En `/dashboard/privacidad`, la card "Finalidades del tratamiento" muestra:
- CUENTA: siempre check verde ✅  
- MARKETING: siempre circulo gris ⭕  
- ANALISIS: siempre circulo gris ⭕  
- COMPARTIR_TERCEROS: siempre circulo gris ⭕  

Esto es incorrecto. Si el usuario selecciono 2 opciones (ej: CUENTA + MARKETING) al registrarse, deberia verse:
- CUENTA: check verde ✅  
- MARKETING: check verde ✅  
- ANALISIS: X rojo ❌  
- COMPARTIR_TERCEROS: X rojo ❌  

### Causa
El HTML en `privacidad.html:61-78` tiene los SVGs hardcodeados. No consulta el estado real de los consentimientos via API.

### Archivo
`src/main/resources/templates/dashboard/privacidad.html` (lineas 61-78)

### Solucion
- Cargar los consentimientos desde `GET /api/v1/consentimiento/mis-preferencias` via HTMX o fetch
- Renderizar cada finalidad con SVG verde ✅ si `activo=true` o rojo ❌ si `activo=false`

## Bug 2 — "Consentimientos otorgados" nunca carga datos reales

### Sintoma
La card "Consentimientos otorgados" muestra "Cargando consentimientos..." indefinidamente. Nunca se cargan los datos reales del historial.

### Causa
`privacidad.html:88-90` tiene un div con texto estatico pero no hay ninguna llamada JS que cargue los datos desde `GET /api/v1/consentimiento/mis-preferencias`.

### Archivo
`src/main/resources/templates/dashboard/privacidad.html` (lineas 81-92)

### Solucion
- Agregar HTMX o fetch para cargar los consentimientos desde la API
- Mostrar tabla con: finalidad, estado (activo/revocado), fecha

## Bug 3 — "Gestionar consentimientos" lleva a pagina de solo lectura

### Sintoma
Click en "Gestionar consentimientos" → lleva a `/consentimiento`. Si el usuario ya otorgo consentimiento previamente, solo ve el mensaje "Preferencias guardadas" sin poder modificar nada.

### Causa
`consentimiento.html` tiene un `th:if="${consentimientoOtorgado}"` que oculta el formulario si ya se otorgo consentimiento. No hay forma de volver a editar.

### Archivos
- `src/main/resources/templates/dashboard/privacidad.html` (linea 91)
- `src/main/resources/templates/auth/consentimiento.html` (linea 39)

### Solucion
- En `/consentimiento`, cuando el usuario ya tiene consentimientos, mostrar el formulario con los checkboxes en el estado actual (pre-marcados segun lo que eligio)
- Agregar boton "Guardar cambios" que actualice (no cree duplicados)
- El boton en privacidad.html debe decir "Editar consentimientos" en vez de "Gestionar consentimientos"

## Bug 4 — Portabilidad: botones "Descargar JSON" y "Descargar CSV" deshabilitados

### Sintoma
Los botones "Descargar JSON" y "Descargar CSV" tienen `disabled` y `title="Proximamente"`. No funcionan.

### Causa
`privacidad.html:102,105` tienen el atributo `disabled` hardcodeado.

### Archivo
`src/main/resources/templates/dashboard/privacidad.html` (lineas 101-108)

### Solucion
- Quitar `disabled` del boton "Descargar JSON"
- Cambiar el `href` al endpoint existente `/api/v1/arcop/portabilidad` (que ya descarga JSON)
- Para CSV, dejarlo deshabilitado o implementar conversion a CSV

## Bug 5 — "Solicitar eliminacion de cuenta" deshabilitado

### Sintoma
El boton rojo "Solicitar eliminacion de cuenta" tiene `disabled` y no hace nada.

### Causa
`privacidad.html:127` tiene el atributo `disabled` hardcodeado.

### Archivo
`src/main/resources/templates/dashboard/privacidad.html` (linea 127)

### Solucion
- Quitar `disabled`
- Conectar el boton al endpoint `DELETE /api/v1/arcop/suprimir` con confirmacion via `hx-confirm` o `confirm()`
- Despues de eliminar, redirigir al login con mensaje
- Respetar Ley 21.719: anonimizar datos, conservar certificados, periodo de gracia 30 dias (ya implementado en ArcopService)
