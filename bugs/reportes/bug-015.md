# Bug-015: Mejoras en admin del Gestor de Contenidos BPO

---

## 1. Que paso?

### Error A: Falta boton "+ Crear nueva carpeta" en detalle del gestor
En la pagina `http://localhost:8080/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001` (detalle del gestor), se listan las subcarpetas existentes y hay un boton "Volver", pero **no existe un boton para crear una nueva subcarpeta** dentro del gestor.

Actualmente si no hay subcarpetas, solo muestra el mensaje "No hay subcarpetas en este gestor." sin ninguna accion para crearlas.

### Error C: Error 403 Forbidden al crear nueva publicacion con archivo adjunto
En la pagina `http://localhost:8080/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001/subcarpetas/b2000000-0000-0000-0000-000000000001/nuevo`, al llenar el formulario (titulo, descripcion, contenido, archivo adjunto) y hacer clic en "Publicar", redirige a la pagina de la subcarpeta pero muestra un error **403 Forbidden**.

El error completo:
```
Whitelabel Error Page
This application has no explicit mapping for /error...
There was an unexpected error (type=Forbidden, status=403).
Forbidden
```

**Causa:** Spring Security tiene proteccion CSRF activada. El formulario usa `enctype="multipart/form-data"` y el token CSRF no se esta incluyendo correctamente en la solicitud multipart, por lo que el servidor rechaza el POST con 403.

**Solucion:** Agregar un campo oculto con el token CSRF dentro del formulario, usando `<input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />`, o tambien se puede configurar SecurityConfig para ignorar CSRF en las rutas `/admin/bpo/**`.

### Error D: Rutas con UUIDs feas en vez de codigos legibles
Todas las URLs del admin usan UUIDs como identificadores en la ruta:
- `http://localhost:8080/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001`
- `http://localhost:8080/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001/subcarpetas/b2000000-0000-0000-0000-000000000001`

En vez de rutas limpias como:
- `http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO`
- `http://localhost:8080/admin/bpo/gestores/GESTOR_EJEMPLO/subcarpetas/carpeta-de-ejemplo`

**Causa:** Las plantillas generan URLs usando `gestor.id` (UUID) en vez de `gestor.codigo` (legible), y SubServicioBPO no tiene campo `codigo` para generar URLs limpias de subcarpetas.

**Orden de ejecucion seguro (paso a paso sin romper nada):**

**Paso 1:** Migracion V25: agregar columna `codigo` a subservicios_bpo y poblar slugs
**Paso 2:** Actualizar plantillas para usar `gestor.codigo` y `subcarpeta.codigo` (NO tocar controlador aun)
**Paso 3:** Compilar y probar — controlador aun acepta UUIDs, todo funciona
**Paso 4:** Actualizar controlador para aceptar TANTO codigos como UUIDs con fallback
**Paso 5:** Compilar y probar — URLs viejas con UUIDs siguen funcionando
**Paso 6:** Ejecutar tests

### Error B: Falta boton "Editar" en cada publicacion
En la pagina `http://localhost:8080/admin/bpo/gestores/a1000000-0000-0000-0000-000000000001/subcarpetas/b2000000-0000-0000-0000-000000000001`, cada publicacion se muestra como una tarjeta con titulo, descripcion, archivo adjunto y un boton **"Eliminar"**, pero **no existe un boton "Editar"** para modificar la publicacion.

Cada tarjeta de publicacion deberia tener DOS botones de accion:
- "Editar" (para modificar titulo, contenido, archivo)
- "Eliminar" (para borrar la publicacion)

@GetMapping("/gestores/{gestorId}/subcarpetas/{subId}/publicaciones/{pubId}/editar")
public String formularioEditarPublicacion(@PathVariable UUID gestorId,
                                           @PathVariable UUID subId,
                                           @PathVariable UUID pubId, Model model) {
    var cuenta = cuentaService.buscarPorId(gestorId).orElseThrow();
    var sub = cuentaService.obtenerSubserviciosPorCuenta(gestorId).stream()
            .filter(s -> s.getId().equals(subId)).findFirst().orElseThrow();

            .orElseThrow(() -> new RuntimeException("Publicacion no encontrada"));
    model.addAttribute("gestor", cuenta);
    model.addAttribute("subcarpeta", sub);
    model.addAttribute("publicacion", new ContenidoBPOCreateDTO(
            contenido.getTitulo(),
            contenido.getDescripcionCorta(),
            contenido.getContenidoHtml(),
            contenido.getSubservicio() != null ? contenido.getSubservicio().getId() : null,
            null  // archivo se maneja aparte
    ));
    return "bpo/admin/formulario-publicacion";

### Cambio 9: Nuevo metodo `actualizarPublicacion` en `ContenidoBPOService.java`
```java
public ContenidoBPO actualizarPublicacion(UUID id, ContenidoBPOCreateDTO dto, UUID usuarioId) {
    ContenidoBPO contenido = contenidoRepository.findById(id)
            .orElseThrow(() -> new BPOContenidoNoEncontradoException("Publicacion no encontrada"));
    contenido.setTitulo(dto.getTitulo());
    contenido.setDescripcionCorta(dto.getDescripcionCorta());
    contenido.setContenidoHtml(dto.getContenidoHtml());
    if (dto.getArchivo() != null && !dto.getArchivo().isEmpty()) {
        var archivoInfo = fileUploadService.subirArchivo(dto.getArchivo(), "bpo");
        contenido.setArchivoUrl(archivoInfo.url());
        contenido.setArchivoNombre(archivoInfo.nombre());
        contenido.setArchivoMime(archivoInfo.mime());
        contenido.setArchivoTamano(archivoInfo.tamano());
    }
    contenido.setActualizadoPor(usuarioId);
    contenido.setUpdatedAt(LocalDateTime.now());
    ContenidoBPO guardado = contenidoRepository.save(contenido);
    auditLogger.registrarEvento("BPO_CONTENIDO_ACTUALIZADO", usuarioId, "ACTUALIZAR",
            "BPO_CONTENIDO", id, Map.of("titulo", dto.getTitulo()));
    return guardado;
}
```

### Cambio 10: Agregar token CSRF en formulario de publicacion en `formulario-publicacion.html`

**Problema:** El formulario POST falla con 403 Forbidden porque el token CSRF no se incluye al usar `enctype="multipart/form-data"`.

**Solucion 1 (recomendada):** Agregar campo oculto CSRF manualmente dentro del `<form>` en `formulario-publicacion.html`:
```html
<form th:action="@{/admin/bpo/gestores/{gid}/subcarpetas/{sid}(gid=${gestor.id},sid=${subcarpeta.id})}"
      th:object="${publicacion}" method="post" enctype="multipart/form-data">
    <!-- Campo CSRF oculto -->
    <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}" />
    ... resto del formulario ...
</form>
```

**Solucion 2 (alternativa):** Deshabilitar CSRF para las rutas de BPO admin en `SecurityConfig.java`:
```java
.ignoringRequestMatchers("/hx/admin/**", "/api/v1/**", "/admin/bpo/**")
```

**Se recomienda la Solucion 1** ya que mantiene la proteccion CSRF activa.

## 5. Comportamiento esperado final

### Para "+ Crear nueva carpeta":
1. Admin entra a `/admin/bpo/gestores/{id}`
2. Ve el boton azul "+ Crear nueva carpeta" al lado del boton "Volver"
3. Hace clic y va a un formulario con campo "Nombre de la carpeta"
4. Escribe un nombre y hace clic en "Guardar" (btn-primary)
5. Vuelve al detalle del gestor y ve la nueva subcarpeta en la lista

   - Boton "Eliminar" (rojo)
