## 1. Síntoma

*Lo que el usuario dijo:*
"La página de incidentes de seguridad muestra los datos como texto feo sin tabla. Además hay roles que sobran (ADMIN sin usuarios, BPO_ADMIN que duplica a SUPERADMIN)."

1. Ir a `http://localhost:8080/admin/incidentes`

3. Al hacer clic, se pega JSON crudo en pantalla

*Pasos para reproducir (Roles):*
1. Ir a la base de datos o `/admin/roles`
2. Existen 8 roles: ADMIN (0 usuarios), SUPERADMIN (1 usuario), BPO_ADMIN (1 usuario), BPO_SUPERVISOR (0 usuarios), BPO_AGENTE (0 usuarios), ESTUDIANTE (~12 usuarios), INSTRUCTOR (1 usuario), ROL DE PRUEBA (0 usuarios)
3. ADMIN y BPO_ADMIN tienen permisos que ya cubre SUPERADMIN

## 2. Comportamiento esperado

### Incidentes
- Tabla con columnas: IP, Usuario, Descripción, Estado (badge), Fecha
- Filtros por estado: Todos / Pendientes / Resueltos
- Botón "Resolver" para marcar como resuelto

### Roles
- Reducir de 8 a 5 roles eliminando: ADMIN, BPO_ADMIN, BPO_SUPERVISOR, ROL DE PRUEBA
- SUPERADMIN unifica todo el poder administrativo
- ESTUDIANTE obtiene permisos de certificaciones
- BPO_AGENTE se mantiene como rol de solo lectura

Página minimalista que recibe JSON de la API y lo muestra como texto sin formato.

### Roles
8 roles, varios redundantes: ADMIN (0 usuarios) duplica a SUPERADMIN, BPO_ADMIN tiene 1 usuario que también es SUPERADMIN, ROL DE PRUEBA sobrante.

## 5. Causa raíz identificada

**Incidentes:** La página se creó como placeholder y nunca se terminó.

**Roles:** Se crearon roles BPO sin revisar si realmente hacían falta. Quedó ADMIN como rol fantasma porque SUPERADMIN ya cubría todo.
